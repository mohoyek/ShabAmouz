بزرگ‌ترین تفاوت لینوکس با سیستم‌های خانگی، جدی بودن مجوزهاست: روی سرور واقعی، همه‌چیز — از خواندن یک فایل تا اجرای یک پورت — با مجوز کنترل می‌شود. بخش بزرگی از آزمون 101 همین مدل مجوزهاست و در عمل، ادمین هر روز با آن کار می‌کند. در این درس ابتدا ابزارهای کار با فایل را مرور می‌کنیم و بعد عمیق وارد دنیای `chmod` و `chown` می‌شویم.

## کار روزمره با فایل‌ها

```bash
mkdir projects                     # ساخت پوشه
mkdir -p projects/2026/web         # ساخت کل زنجیره مسیر
cp file.txt backup.txt             # کپی فایل
cp -r projects /tmp/               # کپی پوشه به‌صورت بازگشتی
mv file.txt /tmp/newname.txt       # جابه‌جایی (و تغییر نام همزمان)
rm file.txt                        # حذف فایل
rm -r projects                     # حذف پوشه با محتوا
rm -rf /                           # جنگ جهانی سوم — هرگز!
```

دستور `find` برای جستجو، قهرمان آزمون 101 است:

```bash
find /etc -name "*.conf"           # همه فایل‌های .conf زیر /etc
find /var -size +100M              # فایل‌های بزرگ‌تر از ۱۰۰ مگابایت
find /home -user reza -mtime -7    # فایل‌های کاربر reza در ۷ روز اخیر
find /tmp -type d -name "cache*"   # فقط پوشه‌ها
```

**لینک‌ها** دو نوع دارند و تفاوت‌شان سؤال پرتکرار آزمون است:

- **لینک نمادین (Symbolic/Soft):** میان‌بر واقعی؛ به مسیر مقصد اشاره می‌کند و اگر اصل حذف شود، شکسته می‌شود. نوع فایل `l` است.
- **لینک سخت (Hard):** نام دوم برای همان داده (همان inode)؛ حذف اصل، لینک سخت را نمی‌شکند. فقط روی همان فایل‌سیستم معتبر است و برای پوشه‌ها مجاز نیست.

```bash
ln -s /var/www/app latest    # لینک نمادین
ln data.txt data-hard.txt    # لینک سخت
ls -li                       # دیدن inode و نوع لینک
```

## مدل مجوزها: rwx برای سه گروه

هر فایل یک مالک (Owner)، یک گروه (Group) و «دیگران» (Others) دارد و برای هر کدام سه مجوز تعریف می‌شود:

| مجوز | روی فایل | روی پوشه |
|---|---|---|
| `r` (4) | خواندن محتوا | دیدن فهرست فایل‌ها |
| `w` (2) | تغییر محتوا | ساخت/حذف فایل داخل پوشه |
| `x` (1) | اجرای برنامه | ورود به پوشه (`cd`) |

خروجی `ls -l` را بخوانید: `-rwxr-x--- 1 reza devops 220 file.sh` — یعنی مالک همه‌چیز دارد، گروه فقط خواندن و اجرا، بقیه هیچ.

**chmod دو سبک دارد.** سبک عددی (اکتال) سریع‌تر است و مجموع ارقام rwx برای هر سه گروه می‌شود:

```bash
chmod 755 script.sh   # rwxr-xr-x — اسکریپت و پوشه‌های عمومی
chmod 644 config.txt  # rw-r--r-- — فایل‌های معمولی
chmod 640 secret.env  # rw-r----- — فایل حساس؛ فقط مالک و گروه
chmod 400 id_rsa      # فقط مالک بخواند — استاندارد کلید SSH
```

سبک نمادین برای تغییر جزئی بهتر است: `chmod u+x file.sh` (به مالک اجرا بده)، `chmod go-w file.txt` (نوشتن را از گروه و دیگران بگیر)، `chmod a=r file.txt` (همه فقط بخوانند).

## مالکیت و umask

```bash
chown reza report.txt          # تغییر مالک
chown reza:devops report.txt   # مالک + گروه همزمان
chgrp devops report.txt        # فقط گروه
chown -R www-data:www-data /var/www  # بازگشتی — رایج در وب‌سرور
```

**umask** تعیین می‌کند فایل تازه‌ساز به‌صورت پیش‌فرض چه مجوزی بگیرد: مجوز کامل (666 برای فایل، 777 برای پوشه) منهای umask. با umask پیش‌فرض `022`، فایل تازه `644` و پوشه تازه `755` می‌شود. سؤال کلاسیک آزمون: «با umask 027 فایل تازه چه مجوزی دارد؟» پاسخ: 640.

- **مجوز خاص:** `chmod 4755` سِت بیت SUID (اجرا با مجوز مالک — مثل `passwd`)، `2755` SGID و `1777` استیکی‌بیت برای `/tmp` (هرکس فقط فایل خودش را حذف کند). این سه، سؤال‌های همیشگی آزمون 101 هستند.
- **سلسله‌مراتب تصمیم:** برای تشخیص دسترسی، مالکیت مالک بر گروه و گروه بر دیگران مقدم است؛ یعنی اگر مالک هستید، «دیگران» حتی اگر اجازه داشته باشند، بی‌اثرند.

## جمع‌بندی

- `cp -r` برای پوشه، `mv` هم جابه‌جایی هم تغییر نام و `find` ابزار جستجوی حرفه‌ای با فیلتر نام، اندازه، کاربر و زمان است.
- لینک نمادین میان‌بر شکستنی است؛ لینک سخت نام دوم برای همان inode و محدود به یک فایل‌سیستم.
- مجوزها rwx برای سه گروه مالک/گروه/دیگران؛ 755 برای اسکریپت‌ها، 644 برای فایل‌ها و 400 برای کلیدهای خصوصی.
- `chown` مالکیت را تغییر می‌دهد و umask مجوز پیش‌فرض فایل‌های تازه را تعیین می‌کند (666 یا 777 منهای umask).
- مجوزهای خاص SUID/SGID/Sticky رفتار اجرا و حذف را تغییر می‌دهند و در آزمون همیشه حاضرند.

برای تمرین: یک پوشه بسازید، یک اسکریپت کوچک با `chmod 750` قفل کنید و با کاربر دوم (بسازید با `useradd`، درس بعد!) امتحان کنید که آیا واقعاً اجرا نمی‌شود. حس عملی مجوزها را فقط همین آزمایش جا می‌اندازد.
