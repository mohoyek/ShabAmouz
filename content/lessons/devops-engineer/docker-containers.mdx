در مسیرهای پایه، برنامه‌ها را مستقیم روی سیستم‌عامل اجرا کردید و هر بار با مشکل کلاسیک «روی سیستم من کار می‌کرد» روبه‌رو شدید. **کانتینر** پاسخ صنعتی به این مشکل است: برنامه با همه وابستگی‌هایش در یک بسته یکتا (Image) بسته‌بندی می‌شود و روی هر سروری یکسان اجرا می‌شود. Docker محبوب‌ترین ابزار ساخت و اجرای این کانتینرهاست و امروز هیچ پایپ‌لاین تحویل نرم‌افزاری بدون آن معنا ندارد.

## کانتینر با ماشین مجازی چه فرقی دارد؟

هر دو «ایزوله‌سازی» می‌دهند اما در سطح متفاوتی:

| ویژگی | ماشین مجازی | کانتینر |
|---|---|---|
| سطح مجازی‌سازی | سخت‌افزار کامل + سیستم‌عامل مهمان | فقط فرایندها؛ کرنل مشترکِ میزبان |
| وزن | چند گیگابایت، راه‌اندازی ده‌ها ثانیه | ده‌ها مگابایت، راه‌اندازی کسری از ثانیه |
| چگالی روی سرور | چند دستگاه | ده‌ها کانتینر |
| کاربرد نمونه | اجرای ویندوز روی سرور لینوکسی | بسته‌بندی سرویس‌های اپلیکیشن |

کانتینر در واقع یک **فرایند ایزوله** در لینوکس است: با namespaceها از بقیه سیستم جدا شده و با cgroups سهم CPU و RAM محدود شده است. چون کرنل مشترک است، شروع کانتینر مثل اجرای یک پروسه سریع است، نه بوت شدن یک سیستم‌عامل.

## سه مفهوم: Image، Container، Dockerfile

- **Image:** قالب فقط-خواندنی که برنامه و وابستگی‌هایش را دارد. ایمیج از **لایه‌ها (Layers)** ساخته می‌شود؛ هر دستور Dockerfile یک لایه اضافه می‌کند و لایه‌ها بین ایمیج‌ها به اشتراک گذاشته و کش می‌شوند.
- **Container:** یک نمونه در حال اجرا از ایمیج + یک لایه نوشتنی روی آن. حذف کانتینر، لایه نوشتنی‌اش را هم می‌برد؛ داده ماندگار به Volume نیاز دارد.
- **Dockerfile:** دستور پخت ایمیج؛ متنی و نسخه‌پذیر در گیت.

نمونه Dockerfile برای یک وب‌اپ کوچک:

```dockerfile
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev
COPY . .
EXPOSE 3000
USER node
CMD ["node", "server.js"]
```

ترتیب سطرها عمدی است: چون `package.json` قبل از کد Copy می‌شود، هر تغییر کد فقط لایه‌های بعد از آن را بازسازی می‌کند و کش لایه `npm ci` سالم می‌ماند — در پایپ‌لاین‌ها این یعنی ساخت چند برابر سریع‌تر.

دستورات روزمره که حفظ‌شان می‌کنید:

```bash
docker build -t shabamouz-web:1.0 .        # ساخت ایمیج از Dockerfile
docker run -d -p 8080:3000 --name web shabamouz-web:1.0
docker ps                                   # کانتینرهای در حال اجرا
docker logs -f web                          # لاگ زنده کانتینر
docker exec -it web sh                      # ورود به شل کانتینر
docker volume create appdata                # حجم ماندگار
```

پرچم `-p 8080:3000` یعنی پورت ۸۰۸۰ میزبان به پورت ۳۰۰۰ کانتینر وصل شود. دقت کنید `-d` اجرا در پس‌زمینه است و `--name` نام قابل‌ارجاع می‌دهد.

## Volume و شبکه؛ دو جایی که تازه‌کارها گیر می‌کنند

**داده ماندگار:** کانتینر «بی‌حالت» (Stateless) طراحی می‌شود؛ هر بازسازی، داده داخلش را پاک می‌کند. هر چیزی که باید بماند — دیتابیس، فایل‌های آپلودی — به Volume می‌رود:

```bash
docker run -d -v pgdata:/var/lib/postgresql/data -e POSTGRES_PASSWORD=s3cret postgres:16
```

**شبکه کانتینرها:** به‌جای IP دستی، کانتینرهای مرتبط را در یک شبکه تعریف‌شده (Bridge) بگذارید؛ آن‌گاه با نام همدیگر را پیدا می‌کنند (DNS داخلی Docker):

```bash
docker network create appnet
docker run -d --name db --network appnet -v pgdata:/var/lib/postgresql/data postgres:16
docker run -d --name web --network appnet -p 8080:3000 shabamouz-web:1.0
```

حالا اپلیکیشن با نام میزبان `db` به دیتابیس می‌رسد — مستقل از IP. این الگو پایه فایل‌های Compose است که در پروژه‌های واقعی همین دو کانتینر را با یک فایل YAML تعریف می‌کنند.

## چند عادت حرفه‌ای از روز اول

1. **ایمیج کوچک بسازید:** پایه Alpine یا نسخه‌های slim؛ ایمیج ۱ گیگابایتیِ بدون دلیل، سرعت پایپ‌لاین و امنیت را می‌کشد.
2. **با root اجرا نکنید:** دستور `USER` در Dockerfile یک خط است اما سطح حمله را جدی کم می‌کند.
3. **نسخه دقیق تعیین کنید:** `FROM node:20-alpine` نه `FROM node:latest`؛ نسخه شناور یعنی ساخت‌های غیرقابل تکرار.
4. **اسکن امنیتی:** با ابزارهایی مثل `docker scan` یا Trivy ایمیج‌ها را برای آسیب‌پذیری‌های شناخته‌شده چک کنید — پیش‌درآمد DevSecOps در سطح بعدی.

## جمع‌بندی

- کانتینر فرایندی ایزوله با کرنل مشترک است؛ سبک‌تر و سریع‌تر از ماشین مجازی.
- ایمیج از لایه‌های فقط-خواندنی ساخته می‌شود و ترتیب دستورات Dockerfile روی سرعت بازسازی اثر مستقیم دارد.
- داده ماندگار به Volume و ارتباط سرویس‌ها به شبکه نام‌دار Docker نیاز دارد.
- ایمیج کوچک، اجرای بدون root و نسخه‌گذاری دقیق، سه عادت پایه‌ای امن و حرفه‌ای است.

برای تمرین: همین Dockerfile را برای یک پروژه کوچک خودتان اجرا کنید؛ بعد کد را تغییر دهید و با `docker build` ببینید کدام لایه‌ها از کش استفاده می‌کنند. سپس کانتینر را پاک کنید و با Volume ببینید داده دیتابیس چطور زنده می‌ماند.
