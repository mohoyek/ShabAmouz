تا این مرحله اپلیکیشن را دستی ساختید و دستی منتشر کردید؛ همان چند دستور که هر بار جایی می‌لغزد. **CI/CD** یعنی همین چرخه ساخت، تست و انتشار به‌صورت خودکار و تکرارپذیر با هر push. پایپ‌لاین، ستون فقرات فرهنگ DevOps است: تغییر کوچک، تست خودکار، انتشار کم‌ریسک. در این درس پایپ‌لاین واقعی را با GitHub Actions — ابزار یکپارچه با گیت‌هاب — می‌سازید.

## CI و CD دقیقاً یعنی چه؟

- **CI (یکپارچه‌سازی پیوسته):** هر push یا Pull Request، کد را Build و تست می‌کند. هدف: خرابی سریع و شفاف — باگی که روز اول شناسایی می‌شود ده برابر ارزان‌تر از باگی است که ماه دوم پیدا می‌شود.
- **CD (تحویل/استقرار پیوسته):** خروجی سالمِ CI خودکار یا نیمه‌خودکار به محیط اجرا می‌رود. «تحویل پیوسته» تا استقرار در محیط staging خودکار است و انتشار نهایی با تأیید انسان؛ «استقرار پیوسته» تا production هم بی‌وقفه می‌رود.

تفاوت را با فرایندهای خودتان تنظیم کنید: بسیاری تیم‌ها به‌درستی CD با تأیید انسانی برای production انتخاب می‌کنند.

## ساختار GitHub Actions

سه مفهوم تودرتو: **Workflow** (کل فایل؛ با رویدادهای trigger)، **Job** (یک ماشین مجازی ایزوله) و **Step** (هر دستور داخل Job):

```yaml
name: CI/CD
on:
  push:
    branches: [main]
  pull_request:

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
      - run: npm ci
      - run: npm test

  build-and-deploy:
    needs: test
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Build image
        run: docker build -t ghcr.io/acme/web:${{ github.sha }} .
      - name: Push image
        run: |
          echo "${{ secrets.GHCR_TOKEN }}" | docker login ghcr.io -u ci --password-stdin
          docker push ghcr.io/acme/web:${{ github.sha }}
      - name: Deploy to server
        run: |
          ssh deployer@prod.example.com \
            "cd /srv/web && docker compose pull && docker compose up -d"
```

این فایل سه الگوی مهم را نشان می‌دهد: تست روی هر push و PR اجرا می‌شود؛ Job استقرار با `needs: test` فقط بعد از تست سبز اجرا می‌شود؛ و تگ ایمیج، هش کامیت (`github.sha`) است تا هر انتشار دقیقاً به کدش گره بخورد — مبنای بازگشت (Rollback) مطمئن.

## قوانین حرفه‌ای پایپ‌لاین

- **شکست سریع:** تست‌های سریع اول، تست‌های سنگین بعد. بازخورد ۳۰ دقیقه‌ای، نظم تیم را می‌کشد.
- **تگ‌گذاری هر خروجی:** هیچ ایمیجی با تگ `latest` به production نرود؛ تگ = هش کامیت یا نسخه semver.
- **Secrets فقط در Secrets:** رمزها را در تنظیمات مخزن (Actions Secrets) نگه دارید؛ در لاگ mask می‌شوند و هرگز در کد نمی‌آیند. هرگز کلید production را در YAML کامیت نکنید.
- **نسخه‌بندی Actionها:** `actions/checkout@v4` نه `@main`؛ پایپ‌لاین پایدار روی نسخه شناور بنا نمی‌شود.
- **Gate محیط production:** از Environment Protection استفاده کنید تا انتشار نیازمند تأیید شخص تعیین‌شده باشد — خط قرمز «چه کسی اجازه انتشار دارد» را خودکار اجرا می‌کند.

## استراتژی‌های انتشار؛ وقتی پایپ‌لاین جدی می‌شود

بعد از پایه، انتخاب استراتژی جایگزینی نسخه در production است:

| استراتژی | ایده | هزینه | مناسب برای |
|---|---|---|---|
| Rolling | جایگزینی تدریجی نسخه‌ها | کم | بیشتر سرویس‌های عادی |
| Blue/Green | دو محیط کامل؛ سوییچ یک‌باره ترافیک | دو برابر منبع | بازگشت فوری |
| Canary | درصد کوچک کاربر به نسخه جدید | پیچیدگی مانیتورینگ | سرویس‌های با مقیاس بزرگ |

K8s از درس قبل Rolling را پیش‌فرض دارد و Canary را با Ingress یا Service Mesh ممکن می‌کند. انتخاب درست به «قدرت بازگشت» و «تحمل ریسک» سرویس شما بستگی دارد — تصمیمی که با داده مانیتورینگ گرفته می‌شود، نه سلیقه.

## جمع‌بندی

- CI یعنی تست خودکار هر تغییر؛ CD یعنی مسیر خودکار تا استقرار، با یا بدون تأیید انسانی.
- ساختار Actions: Workflow → Job → Step؛ `needs` ترتیب را می‌سازد و `if` شرط را.
- هر خروجی با تگ یکتا (هش کامیت) منتشر می‌شود؛ این تگ‌ها مبنای Rollback هستند.
- رمزها فقط در Secrets و Actionها فقط با نسخه ثابت استفاده می‌شوند.
- Rolling، Blue/Green و Canary سه استراتژی جایگزینی نسخه با معاوضه ریسک/هزینه متفاوت‌اند.

برای تمرین: در یک ریپازیتوری کوچک، Workflow دو Job‌ای همین درس را بسازید (تست + build)؛ عمداً یک تست را خراب کنید و ببینید Job استقرار اجرا نمی‌شود. سپس یک Secret اضافه کنید و در لاگ ببینید مقدارش mask شده است.
