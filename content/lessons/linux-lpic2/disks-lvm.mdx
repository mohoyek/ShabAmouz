سخت‌ترین بهانه‌های نصفه‌شبِ ادمین، دیسک‌ها هستند: «فضا پر شده» و «دیتابیس قطع شد». آزمون LPIC-2 (آزمون 201) این حوزه را با اسم کامل می‌خواهد: پارتیشن‌بندی، فایل‌سیستم، LVM و RAID. در این درس یاد می‌گیرید دیسک اضافه را از صفر به سیستم اضافه کنید، با LVM فضا را انعطاف‌پذیر کنید و با RAID تحمل خطا بسازید.

## پارتیشن‌بندی: MBR یا GPT؟

دو استاندارد جدول پارتیشن وجود دارد و مقایسه‌شان سؤال کلاسیک آزمون است:

| ویژگی | MBR | GPT |
|---|---|---|
| بیشینه دیسک | ۲ ترابایت | ۹.۴ زتابایت |
| تعداد پارتیشن اصلی | ۴ (با extended) | ۱۲۸ |
| بوت مدرن (UEFI) | خیر | بله |
| جدول پشتیبان | ندارد | دارد |

نام دیسک‌ها هم قاعده دارد: `/dev/sda` دیسک اول SATA/SAS، پارتیشن‌ها `/dev/sda1` و `/dev/sda2`؛ در NVMe نام‌گذاری `/dev/nvme0n1p1` است. ابزارهای کار:

```bash
lsblk                          # نقشه درختی دیسک‌ها و پارتیشن‌ها
sudo fdisk /dev/sdb            # پارتیشن‌بندی تعاملی (MBR/GPT)
sudo parted /dev/sdb mklabel gpt          # جدول GPT
sudo parted /dev/sdb mkpart data 1MiB 10GiB  # پارتیشن ۱۰ گیگ
sudo gdisk /dev/sdb            # مثل fdisk ولی مخصوص GPT
```

## فایل‌سیستم و mount

پارتیشن خالی است تا روی آن **فایل‌سیستم** بسازیم. ext4 انتخاب عمومی لینوکس و XFS انتخاب رایج RHEL برای داده حجیم است (سؤال آزمون: XFS قابل کوچک‌شدن نیست!).

```bash
sudo mkfs.ext4 /dev/sdb1       # ساخت فایل‌سیستم ext4
sudo mkfs.xfs /dev/sdc1        # ساخت فایل‌سیستم xfs
sudo mkdir /data && sudo mount /dev/sdb1 /data    # اتصال موقت
df -h                          # فضای مصرفی هر mount
du -sh /var                    # حجم مصرفی یک پوشه
sudo umount /data              # جدا کردن
```

برای ماندگاری بعد از ری‌بوت، پارتیشن باید در `/etc/fstab` ثبت شود — فایلی که اشتباه در آن، سیستم را از بوت می‌اندازد:

```
UUID=8f3c...  /data  ext4  defaults  0  2
```

همیشه به‌جای نام دستگاه از **UUID** (`blkid /dev/sdb1`) استفاده کنید؛ نام دستگاه‌ها بعد از تغییر سخت‌افزار ممکن است عوض شود ولی UUID ثابت است. قبل از ری‌بوت، با `sudo mount -a` و `findmnt` درستی fstab را تست کنید.

## LVM: فضای انعطاف‌پذیر

مشکل پارتیشن ساده این است که اندازه‌اش ثابت است. **LVM** یک لایه بین دیسک و فایل‌سیستم اضافه می‌کند با سه سطح: **PV** (حجم فیزیکی = دیسک/پارتیشن)، **VG** (گروه حجمی = مخزن فضای همه PVها) و **LV** (حجم منطقی = چیزی که فرمت و mount می‌شود). نتیجه: هر وقت جا کم آمدید، یک دیسک به VG اضافه و LV را زنده بزرگ کنید.

```bash
sudo pvcreate /dev/sdb1 /dev/sdc1          # ۱) ساخت PV
sudo vgcreate vgdata /dev/sdb1 /dev/sdc1   # ۲) ساخت VG
sudo lvcreate -n lvapp -L 20G vgdata       # ۳) ساخت LV بیست گیگ
sudo mkfs.ext4 /dev/vgdata/lvapp           # ۴) فرمت
sudo lvdisplay vgdata                      # وضعیت LVها

# بزرگ کردن زنده: +۵ گیگ
sudo lvextend -L +5G /dev/vgdata/lvapp
sudo resize2fs /dev/vgdata/lvapp           # ext4
sudo xfs_growfs /data                      # برای xfs (نقطه mount)
sudo vgs                                   # فضای آزاد VG
```

سؤال محبوب آزمون: تفاوت `resize2fs` (ext4، آدرس دستگاه) و `xfs_growfs` (xfs، آدرس نقطه mount) — و اینکه XFS کاهش اندازه ندارد؛ برای جابه‌جایی باید پشتیبان بگیرید و از نو بسازید.

## RAID نرم‌افزاری با mdadm

**RAID** چند دیسک را به‌شکل یک دیسک منطقی ترکیب می‌کند. سطح‌های پرتکرار آزمون:

| سطح | دیسک لازم | ویژگی |
|---|---|---|
| RAID 0 (Stripe) | ۲ | سرعت بالا، بدون تحمل خطا |
| RAID 1 (Mirror) | ۲ | آینه کامل؛ با مرگ یک دیسک زنده می‌مانید |
| RAID 5 | ۳ | آینه پخش‌شده؛ تحمل مرگ یک دیسک |
| RAID 6 | ۴ | تحمل مرگ هم‌زمان دو دیسک |
| RAID 10 | ۴ | ترکیب 0 و 1؛ سرعت + تحمل خطا |

```bash
sudo mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/sdb1 /dev/sdc1
cat /proc/mdstat                # وضعیت آرایه و بازسازی
sudo mdadm --detail /dev/md0    # جزئیات و وضعیت دیسک‌های عضو
sudo mdadm /dev/md0 --fail /dev/sdc1 --remove /dev/sdc1   # شبیه‌سازی خرابی
sudo mdadm /dev/md0 --add /dev/sdd1                       # دیسک جایگزین
```

ترکیب معروف: **LVM روی RAID** — تحمل خطا از RAID و انعطاف فضا از LVM. و یادتان باشد RAID جای **بکاپ** را نمی‌گیرد: حذف اشتباهی فایل، روی RAID هم حذف می‌شود!

## جمع‌بندی

- GPT جایگزین مدرن MBR است: پارتیشن ۱۲۸تایی، دیسک تا ۹.۴ زتابایت و سازگار با UEFI.
- فایل‌سیستم با `mkfs.ext4` یا `mkfs.xfs` ساخته و با `mount` و ثبت در fstab (با UUID) دائمی می‌شود.
- LVM با سه سطح PV→VG→LV فضای دیسک را انعطاف‌پذیر می‌کند؛ بزرگ‌کردن زنده با `lvextend` و سپس `resize2fs` یا `xfs_growfs`.
- RAID 1 آینه دو دیسک، RAID 5 حداقل سه دیسک با تحمل یک خرابی و RAID 6 دو خرابی هم‌زمان؛ مدیریت با mdadm و مانیتور `/proc/mdstat`.
- RAID بکاپ نیست؛ هر راهکار جدی، هر دو را دارد.

برای تمرین: در ماشین مجازی دو دیسک ۵ گیگ اضافه کنید، با LVM یک LV بسازید، پُرش کنید و جلوی چشم خودتان بزرگش کنید. بعد mdadm RAID 1 بسازید و یک دیسک را fail کنید تا فرایند بازسازی را ببینید.
