در درس قبل مخزن را ساختیم و با سه ناحیه گیت آشنا شدیم. این درس مهم‌ترین درس کل مسیر است: چرخه کاری روزانه‌ای که هر روز صدها بار تکرار می‌کنید. بعد از این درس، عملاً کار کردن با گیت را بلدید؛ فقط همکاری با اینترنت باقی مانده است.

## git status؛ حالا کجای ماجرایم؟

قبل از هر کار دیگری، این دستور را یاد بگیرید؛ رفیق دائمی شماست:

```
git status
```

خروجی سه نوع خبر می‌دهد: کدام فایل‌ها **آماده کامیت** هستند (سبز)، کدام فایل‌ها **تغییر کرده ولی آماده نیستند** (قرمز) و کدام فایل‌ها کاملاً **ردیابی‌نشده** (Untracked) یعنی گیت اصلاً از وجودشان خبر ندارد.

بعد از `git init` روی یک پوشه تازه، خروجی می‌گوید `nothing to commit` یعنی «هیچی نیست، همه‌چیز مرتب است». حالا یک فایل بسازید:

```
echo "سلام گیت" > notes.txt
git status
```

این بار گیت `notes.txt` را با برچسب Untracked نشان می‌دهد.

## git add؛ انتخاب تغییرات

دستور `add` فایل را از پوشه کاری به ناحیه استیجینگ می‌برد؛ یعنی «این تغییر را برای کامیت بعدی انتخاب کردم»:

```
git add notes.txt       فقط این فایل
git add .               همه تغییرات پوشه جاری و زیرپوشه‌ها
```

بعد از اجرا، `git status` را دوباره بزنید: نام فایل حالا سبز است و زیرش نوشته `new file`. این چراغ‌راهنمای دو رنگ، بزرگ‌ترین کمک گیت به شماست؛ قبل از هر کامیت چکش کنید.

نکته ظریف: اگر بعد از `add` باز هم فایل را ویرایش کنید، نسخه جدید دوباره قرمز می‌شود؛ چون گیت همان نسخه لحظه `add` را در سبد گذاشته و تغییرات بعدی هنوز بیرون هستند. باید دوباره `add` بزنید.

## git commit؛ ثبت در تاریخچه

حالا لحظه ثبت است:

```
git commit -m "افزودن فایل یادداشت اولیه"
```

پارامتر `-m` پیام کامیت را می‌گیرد. خروجی خلاصه‌ای می‌دهد: چند فایل تغییر کرد، چند خط اضافه شد و یک **شناسه یکتا** (مثل `a1b2c3d`) به این نقطه از تاریخچه اختصاص یافت.

### پیام کامیت خوب

پیام کامیت سند آینده پروژه است. سه قاعده ساده:

- فعل و قصد را بنویسید: «افزودن فرم لاگین»، «اصلاح محاسبه مبلغ سبد»؛ نه «تغییرات» و «آپدیت».
- یک کامیت، یک موضوع؛ کامیت‌های بزرگ و مخلوط را کسی نمی‌تواند بخواند.
- پیام کاملاً اختصاری ننویسید؛ شش ماه بعد، تنها خواننده پیام، خودِ فراموشکار شما هستید.

## git log؛ تاریخچه را ببین

فهرست کامیت‌های ثبت‌شده:

```
git log
```

خروجی برای هر کامیت نشان می‌دهد: شناسه کامل، نام و ایمیل نویسنده، تاریخ و پیام. نسخه‌های خلاصه‌تر:

```
git log --oneline       هر کامیت در یک سطر با شناسه کوتاه
```

از شناسه کوتاه بعداً برای بازگشت به گذشته استفاده خواهیم کرد.

## چرخه کامل؛ سناریوی واقعی

همه را در یک گردش واقعی ببینید:

```
git status
git add index.html
git commit -m "ساخت صفحه اصلی با عنوان و پاراگراف معرفی"
echo "<p>بخش درباره ما</p>" >> index.html
git status
git add index.html
git commit -m "افزودن بخش درباره ما"
git log --oneline
```

الگو همیشه همین است: **status → add → commit**. صدها بار تکرارش می‌کنید تا شبیه نفس کشیدن شود. این چرخه حتی یک بار به اینترنت نیاز ندارد؛ گیت روی سیستم شما کامل کار می‌کند.

## جمع‌بندی

- `git status` وضعیت سه ناحیه را نشان می‌دهد؛ قبل و بعد از هر دستور بزنید.
- `git add` انتخاب می‌کند چه چیزی در کامیت بعدی باشد؛ `git add .` یعنی همه چیز.
- `git commit -m` با یک پیام معنادار نقطه بازیابی جدید می‌سازد.
- `git log --oneline` تاریخچه فشرده و خوانا را می‌دهد.

برای تمرین: پنج کامیت با پیام‌های معنادار در مخزن تمرینی‌تان بسازید. در درس بعد این تاریخچه را به گیت‌هاب می‌بریم.
