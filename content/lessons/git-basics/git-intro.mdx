اگر تا حالا فایل‌هایی با نام `final-version2-آخرین-حقیقی.docx` داشته باشید، عملاً نسخه‌بندی دستی کرده‌اید و می‌دانید چقدر شکننده است. گیت ابزاری است که این کار را دقیق، خودکار و قابل بازگشت می‌کند. در این درس مفهوم کنترل نسخه را می‌فهمیم، گیت را نصب می‌کنیم و اولین مخزن را می‌سازیم.

## کنترل نسخه چیست و چرا گیت؟

**سیستم کنترل نسخه (Version Control)** به شما اجازه می‌دهد از وضعیت پروژه در لحظه‌های مختلف «عکس ذهنی» بگیرید و هر زمان به هر کدام برگردید. مزایای واقعی:

- **بازگشت به گذشته:** هر تغییری خراب کرد، یک دستور فاصله تا نسخه سالم قبلی.
- **تاریخچه مستند:** برای هر تغییر، چه کسی و چرا، ثبت می‌شود.
- **کار گروهی:** چند نفر روی یک پروژه کار می‌کنند و گیت تغییرات را ترکیب می‌کند.

**گیت (Git)** محبوب‌ترین کنترل نسخه دنیاست؛ رایگان، متن‌باز و سریع. مهم‌ترین نکته فنی: گیت به‌جای ذخیره فایل‌های تغییر‌کرده به‌صورت تک‌تک، در هر کامیت یک **عکس کامل از وضعیت پروژه (Snapshot)** نگه می‌دارد؛ به همین دلیل بازگشت به گذشته سریع و مطمئن است.

## سه ناحیه گیت

قلب فهمیدن گیت این است که فایل شما بین سه ناحیه جابه‌جا می‌شود:

1. **پوشه کاری (Working Directory):** جایی که واقعاً کد می‌نویسید؛ همان پوشه پروژه.
2. **ناحیه آماده‌سازی (Staging Area):** سبد انتخاب؛ تغییراتی که می‌خواهید در کامیت بعدی باشند را اینجا می‌گذارید.
3. **مخزن (Repository):** آرشیو تاریخچه؛ کامیت‌های نهایی اینجا ذخیره می‌شوند.

چرا اصلاً مرحله استیجینگ وجود دارد؟ چون معمولاً هم‌زمان چند تغییر نامرتبط انجام می‌دهید؛ استیجینگ اجازه می‌دهد هر کامیت فقط شامل یک تغییر منطقی و مرتبط باشد. این تصمیم دو مرحله‌ای، اولین روزها عجیب به نظر می‌رسد اما بعداً بزرگ‌ترین نقطه قوت گیت می‌شود.

## نصب گیت

از سایت رسمی `git-scm.com` نسخه مخصوص سیستم‌عاملتان را بگیرید و نصب کنید. در ویندوز، گزینه‌های پیش‌فرض نصب‌کننده برای شروع کاملاً مناسب‌اند. بعد از نصب، صحت نصب را با این دستور چک کنید:

```
git --version
```

اگر شماره نسخه نمایش داده شد، گیت آماده است.

## پیکربندی اولیه: گیت شما را نمی‌شناسد

گیت برای ثبت هر کامیت باید بداند «چه کسی» این تغییر را داده. پس قبل از هر کاری نام و ایمیل را معرفی کنید؛ این یک‌بار برای همیشه انجام می‌شود و پرچم `--global` یعنی برای همه پروژه‌های این کامپیوتر:

```
git config --global user.name "Ali Rezaei"
git config --global user.email "ali@example.com"
```

هر زمان بخواهید فهرست تنظیمات فعلی را ببینید:

```
git config --list
```

## ساخت اولین مخزن با git init

گیت فقط وقتی پروژه‌ای را مدیریت می‌کند که آن پوشه یک **مخزن (Repository)** باشد. تبدیل پوشه معمولی به مخزن یک دستور است:

```
mkdir my-first-repo
cd my-first-repo
git init
```

خروجی می‌گوید مخزن خالی گیت در مسیر `.git/` ساخته شده. پوشه مخفی `.git` مغز گیت است: کل تاریخچه و تنظیمات آنجا ذخیره می‌شود؛ هرگز محتوایش را دستی ویرایش نکنید و موقع فشرده‌سازی یا کپی پروژه، این پوشه را حذف نکنید.

از این لحظه به بعد گیت همه چیز را می‌بیند ولی هنوز چیزی «ثبت» نشده است؛ ثبت یعنی کامیت و موضوع درس بعدی است.

## جمع‌بندی

- گیت از تاریخچه پروژه عکس کامل (Snapshot) ذخیره می‌کند و بازگشت به هر نقطه را ساده می‌سازد.
- ساختار سه‌ناحیه‌ای: پوشه کاری، استیجینگ و مخزن؛ کامیت فقط از ناحیه استیجینگ انجام می‌شود.
- نصب با `git --version` بررسی می‌شود و نام و ایمیل با `git config --global` معرفی می‌شوند.
- `git init` یک پوشه معمولی را به مخزن تبدیل می‌کند؛ پوشه `.git` را دست‌نخورده نگه دارید.

برای تمرین: مخزن اولیه را بسازید و در درس بعد اولین کامیت تاریخچه‌تان را ثبت می‌کنیم.
