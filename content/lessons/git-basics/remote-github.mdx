تا اینجا تاریخچه پروژه فقط روی سیستم شماست؛ اگر لپ‌تاپ گم شود، همه‌چیز می‌رود. **مخزن ریموت** نسخه‌ای از پروژه روی اینترنت است و **گیت‌هاب (GitHub)** بزرگ‌ترین میزبان این مخزن‌ها. در این درس پروژه‌مان را دوطرفه به ابر وصل می‌کنیم.

## دو سناریوی شروع

با ریموت به دو شکل برخورد می‌کنید و باید هر دو را بلد باشید:

- **پروژه از صفر خودتان:** مخزن محلی را با `git init` ساخته‌اید و حالا می‌خواهید آن را به گیت‌هاب وصل کنید.
- **پروژه دیگران:** نسخه آماده‌ای روی گیت‌هاب است و می‌خواهید روی سیستم خودتان کار کنید.

## گرفتن پروژه با git clone

سناریوی دوم ساده‌تر است؛ دستور `clone` کل مخزن را با همه تاریخچه‌اش دانلود می‌کند:

```
git clone https://github.com/user/repo.git
```

یک پوشه به نام `repo` ساخته می‌شود که خودش مخزن گیت است؛ حتی نیازی به `git init` نیست. داخل آن، اتصال به ریموت از قبل برقرار است. فهرست ریموت‌های متصل را همیشه می‌توانید ببینید:

```
git remote -v
```

نام پیش‌فرض ریموت اصلی `origin` است؛ این نام را به‌خاطر بسپارید چون در دستورهای بعدی مدام می‌بینید.

## وصل‌کردن مخزن محلی به گیت‌هاب

سناریوی اول کمی طولانی‌تر است. مراحل:

1. در گیت‌هاب یک مخزن **خالی** بسازید (بدون فایل README، تا تداخل نسازد).
2. آدرس مخزن جدید را کپی کنید و به مخزن محلی معرفی کنید:

```
git remote add origin https://github.com/you/repo.git
```

3. تاریخچه محلی را برای اولین بار ارسال کنید:

```
git push -u origin main
```

پرچم `-u` (مخفف upstream) یک‌بار استفاده می‌شود و کارش این است که بگوید «برنچ main این مخزن محلی به برنچ main روی origin وصل است». بعد از آن، پوش‌های بعدی فقط `git push` می‌خواهند.

## push و pull؛ دو راه یک‌طرفه

ارتباط با ریموت دو جهت دارد:

- **push:** کامیت‌های محلی را به ریموت می‌فرستد؛ یعنی «کارم تمام شد، در ابر ذخیره کن».
- **pull:** کامیت‌های جدید ریموت را می‌گیرد و با تاریخچه محلی ترکیب می‌کند؛ یعنی «ببین بقیه چه کاری کرده‌اند، بیاور پیش من».

قانون طلایی همکاری: قبل از شروع کار روزانه و قبل از هر push، یک `git pull` بزنید تا تاریخچه شما به‌روز باشد و تداخل (Conflict) کمتر پیش بیاید.

## گردش کار روزانه

همه چیز را در قالب کار یک روز عادی جمع می‌کنیم:

```
git pull
git status
git add auth-form.js
git commit -m "افزودن اعتبارسنجی ایمیل به فرم لاگین"
git push
```

اگر گیت‌هاب در هنگام push خواست احراز هویت، از توکن شخصی (Personal Access Token) استفاده کنید؛ گیت‌هاب دیگر رمز عبور معمولی در خط فرمان نمی‌پذیرد.

## چرا این معماری فوق‌العاده است؟

نکته ظریف: گیت **توزیع‌شده** است. هر نفر، کپی کامل مخزن را دارد؛ ریموت فقط یک «همکار همیشه روشن» است، نه یک دربان مرکزی. یعنی می‌توانید کاملاً آفلاین کار کنید، ده کامیت بزنید و بعداً یک‌جا push کنید؛ این آزادی یکی از دلایل غلبه گیت بر رقباست.

## جمع‌بندی

- `git clone` مخزن ریموت را با تاریخچه کامل به سیستم می‌آورد؛ نام پیش‌فرض ریموت `origin` است.
- برای مخزن محلی موجود، `git remote add origin` و سپس `git push -u origin main` اتصال اولیه را می‌سازد.
- `push` یعنی ارسال کامیت‌ها به ابر و `pull` یعنی گرفتن تغییرات همکاران.
- گردش روزانه استاندارد: pull، سپس کار، سپس add و commit، و در پایان push.
